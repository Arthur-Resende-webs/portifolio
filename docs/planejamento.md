Arthur Resende Webs — Planejamento

1. Visão geral

Nome: Arthur Resende Webs
Posicionamento: desenvolvedor independente, com portfólio próprio.
Objetivo: apresentar o desenvolvedor, exibir seus projetos e facilitar o contato profissional.

O portfólio será uma página web responsiva, com páginas individuais para apresentar cada projeto.

2. Identidade visual

- Estilo moderno, futurista e profissional.
- Fundo escuro com detalhes em roxo e azul.
- Tipografia clara e legível.
- Efeitos de brilho discretos.
- Animações suaves.
- Interface adaptada para computadores e celulares.
- Idioma: português.

Paleta de cores de referência

- Fundo principal: "#0B0D17"
- Roxo: "#8B5CF6"
- Azul: "#3B82F6"
- Texto claro: "#E2E8F0"

As cores poderão receber pequenos ajustes durante a implementação, mantendo a identidade visual.

3. Estrutura da página inicial

A página inicial terá seis áreas, nesta ordem:

1. Cabeçalho fixo.
2. Início.
3. Sobre mim.
4. Projetos.
5. Contato.
6. Rodapé.

3.1. Cabeçalho

- Navegação fixa durante a rolagem.
- Identidade visual com o nome Arthur Resende Webs.
- Links: Início, Sobre mim e Projetos.
- Navegação com rolagem suave.
- No celular, utilizar um menu compacto aberto por um ícone.
- Aparência discreta, com fundo escuro e detalhes roxos.

Os links principais navegam entre seções da mesma página inicial.

3.2. Início

Título principal: Transformando ideias em web.

Texto de apresentação:

Olá! Sou Arthur, desenvolvedor independente, explorando ideias e transformando-as em projetos para a web.

Composição visual:

- Texto à esquerda.
- Painel decorativo de código à direita.
- Indicador discreto de rolagem na parte inferior.
- No celular, o painel de código aparece abaixo do texto.
- Não haverá botão principal de chamada para ação no destaque inicial.

O painel de código terá como referência visual:

"const ideia = { criar: true, inovar: true };"

Esse trecho será um elemento decorativo da interface.

3.3. Sobre mim

Título: Criatividade com propósito.

Texto:

Sou Arthur, desenvolvedor independente. Gosto de explorar ideias, experimentar possibilidades e transformá-las em projetos para a web.

Procuro desenvolver cada projeto com atenção à organização, à experiência de quem vai utilizá-lo e aos detalhes visuais. Cada novo desafio também é uma oportunidade de aprender e evoluir.

Elementos visuais complementares:

- Ideias.
- Desenvolvimento.

A seção terá um equilíbrio entre apresentação pessoal e abordagem profissional, sem informações pessoais desnecessárias.

3.4. Projetos

Título de referência: Projetos em construção.

A seção apresentará três projetos em cards verticais, com um projeto por linha.

Cada card terá:

- Capa gráfica própria.
- Nome do projeto.
- Descrição breve.
- Status verdadeiro de desenvolvimento.
- Link para a página individual do projeto.

As capas serão ilustrações gráficas relacionadas ao tema de cada aplicação, evitando fotografias genéricas.

Projeto 1 — Organizador Financeiro Pessoal

Conceito: organizar despesas, acompanhar valores e visualizar informações financeiras.

Direção visual: gráficos, saldos e elementos financeiros em roxo, azul e ciano.

Status inicial: Planejado.

Projeto 2 — ColorLab

Conceito: explorar cores e criar paletas para projetos visuais.

Direção visual: amostras de cores, formas geométricas e elementos criativos.

Status inicial: Planejado.

Projeto 3 — Organizador de Rotina

Conceito: organizar tarefas, prioridades e acompanhar o progresso.

Direção visual: calendários, listas, indicadores de progresso e elementos de produtividade.

Status inicial: Planejado.

Regras de status

Os status serão atualizados conforme o progresso real:

- Planejado.
- Em desenvolvimento.
- Concluído.

Um projeto não será apresentado como concluído enquanto não estiver realmente pronto.

3.5. Contato

Título: Vamos conversar?

A seção convidará visitantes a conversar sobre ideias, projetos para a web e possíveis trabalhos.

Elementos:

- Texto breve de apresentação.
- Botão para enviar um e-mail.
- Endereço de e-mail profissional configurado durante a implementação.

Não haverá formulário de contato nem links para redes sociais nesta versão inicial.

3.6. Rodapé

O rodapé será minimalista e conterá:

- Nome Arthur Resende Webs.
- Frase do portfólio.
- Direitos autorais.

Texto de referência:

© 2026 Arthur Resende Webs. Todos os direitos reservados.

O ano poderá ser atualizado conforme necessário.

4. Páginas individuais dos projetos

Cada projeto terá uma página própria, com a mesma identidade visual do portfólio.

Cada página poderá conter:

1. Capa visual grande.
2. Nome e descrição.
3. Status atual.
4. Apresentação do objetivo.
5. Recursos previstos e recursos implementados, claramente diferenciados.
6. Imagens reais da aplicação quando disponíveis.
7. Navegação de retorno ao portfólio.
8. Botão para abrir a aplicação somente quando ela estiver funcional.

Enquanto um projeto estiver apenas planejado, sua página apresentará a proposta sem sugerir que já existe uma aplicação funcional.

O formato escolhido é uma apresentação visual, não um relatório técnico extenso.

5. Responsividade e interação

- O layout deve se adaptar a telas grandes e pequenas.
- O menu mobile será compacto.
- Os cards continuarão organizados verticalmente.
- As animações serão suaves e discretas.
- A rolagem entre as seções será suave.
- A interface deverá continuar legível mesmo quando animações ou efeitos visuais não forem exibidos.

- [ ] Painel de código decorativo no destaque inicial.
- [ ] Seção Sobre mim com o texto aprovado.
- [ ] Três cards verticais com capas próprias.
- [ ] Status atualizado conforme o progresso real.
- [ ] Páginas individuais funcionando.
- [ ] Botões de acesso às aplicações exibidos somente quando disponíveis.
- [ ] Botão de e-mail configurado corretamente.
- [ ] Rodapé minimalista.
- [ ] Contraste e legibilidade adequados.
- [ ] Animações discretas.

8. Ordem de trabalho

1. Criar a estrutura de pastas e arquivos.
2. Implementar a página inicial conforme o planejamento.
3. Ajustar a interface para computadores e celulares.
4. Implementar as páginas individuais dos projetos.
5. Testar navegação, links e apresentação visual.
6. Revisar acessibilidade, desempenho e responsividade.
7. Publicar o portfólio no GitHub Pages.
8. Desenvolver os três projetos separadamente, em etapas futuras.

9. Limites do escopo inicial

O primeiro objetivo é construir o portfólio. Os três projetos apresentados são ideias futuras e não fazem parte da primeira implementação funcional do site.

Nenhuma funcionalidade deverá ser descrita como pronta antes de ser implementada e testada.

Estado atual: portfólio implementado; os três projetos (Finora, ColorLab e Nexus) estão funcionais, com seção de Serviços e contato por e-mail.
